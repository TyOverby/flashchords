## Application: Guitar Chords
I want you to build an interactive guitar chords flash card web app as a pure
Javascript React SPA, with a layout that is optimized for mobile.  The two
basic modes should be “identify chord names from looking at the finger
placement” and “set finger placement based on the chord names”.

A major part of this app is going to be the fretboard display for finger
placement, so start there, with an SVG-based UI for showing finger placement on
the fretboard.  For now, only worry about open chords with the possibility of
muted strings.  This UI should also be amenable for user interaction in the
“set finger placement based on chord name” mode, where users can tap on
locations to set them.  Make this a stateless react component that takes the
current finger positions and a setter for positions as input.

The application homepage should have two major components: 

1. A button that takes you to a list of all chords, and also has a UI for
   adding a new chord to the database.  Adding a new chord involves giving it a
   name and a fingering.  Some chords have multiple fingerings for the same
   name, so don’t key the chord off of the name, generate a random ID and use
   that instead.  The page with the list of chords should also allow you to
   remove chords from the database.
2. A list of “flashcard decks” that the user can pick to start a flashcard
   session.  This list should also be editable, with delete buttons for  each

When the user clicks on one of the card decks, it pops up the main quiz UI.
The main quiz UI has the deck name at the top, alongside a UI to change the
“mode” for the quiz.  The mode-selector UI should look like “A -> [unicode
filled circle]”, where the direction of the arrow determines which way the user
is guessing, “A -> •” corresponds to “guess the fingerings from the chord
name”, “A <- •” corresponds to “guess the chord name from the fingering”, and
“A <-> •” will make the quiz randomly choose between modes for each card.

For “guess fingerings based on chord name”, the user is presented with the name
of the chord and a blank fretboard UI.  The fretboard defaults to “all strings
open” (aka, strum all strings, no fingers are pressing on frets).  When the
user clicks on a string in one of the fretboard positions, it adds a black dot
at that position.  Tapping anywhere else on the string will move the dot to the
new location.  Above the fretboard is a clickable region that will mute the
string in question.  Muting the string will make the string slightly
transparent, and will display an “X” in the clickable region that the user
tapped.  When the user is done selecting the finger positions, they click on a
“guess” button underneath the fretboard and their guess is checked against the
correct answer.  If they got it right, then the text “Correct!” shows up for
half a second, and it progresses to the next question.  If the user got it
wrong, then a new fretboard is show, where green circles are shown for the
positions that the user got correct, and a slightly transparent red circle is
used for incorrect positions.  Any missing positions are shown in black.
(note: this means that the “fretboard rendering” component will need to be able
to display multiple positions on the same string in case the user got the
correct string, but the wrong position, in which case one red circle and one
black circle will be displayed.)

For “Guess chord name based on fingering”, the fretboard with correct finger
positions is displayed, along with a list buttons for the chord names that they
can choose.  The chord name options are only those that are a part of the
current flash card deck.  If the user selects the right chord name, then
“Correct!” is shown for half a second, and then move on to the next question.
If the user guesses incorrectly, then the text “Try again!” is shown, and the
button that the user clicked is disabled so that they can’t click it again.
This proceeds until they get it right.

The chords database and deck database should be stored in localstorage, and
have an “export to json” feature.
